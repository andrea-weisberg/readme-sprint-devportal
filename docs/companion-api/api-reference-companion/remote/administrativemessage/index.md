<p><a href="#Tokenization">Administrative Message – Tokenization</a> – Sends tokenization related messages to the client.</p>
<p><a href="#3DSecure">Administrative Message – 3D Secure OTP</a> – Sends message with 3D Secure OTP.</p>

<h1><a id="Tokenization"></a>Administrative Message – Tokenization Related Messages</h1>
<p>Sends tokenization related messages to the client.</p>
<p>Please click <a href="https://developer.sprint.paymentology.com/administrative-message-values/">here</a> for more information on <span className="xml-highlight">messageName </span>data field and the related data which is sent with these messages.</p>

#### Path parameters

| Parameter | type | Limits | required | Description |
|---|---|---|:--:|---|
| terminalID | String | 10 characters | ✓ | <p>The Paymentology issued terminal id of the terminal requesting the transaction</p> |
| reference | String | 1-255 characters | ✓ | <p>The reference of the wallet to retrieve the balance for</p> |
| messageName | String | 0-2048 characters | ✓ | <p>The name of the administrative message being sent. Please see method description for more information in this field. Click <a href="https://developer.sprint.paymentology.com/administrative-message-values/">here</a> for more info on the types of messages for this field.</p> |
| messageData | String | 0-2048 characters | ✓ | <p>The administrative message data sent over in a <a href="https://developer.sprint.paymentology.com/companion-api/klv-lookup/">KLV format</a></p> |
| transactionID | String | 1-255 characters | ✓ | <p>Transaction id number generated by the calling client. Note that the Transaction id is not a unique value and may be duplicated over time.</p> |
| transactionDate | Date |  | ✓ | <p>Transaction date generated by the calling client</p> |
| checksum | String |  | ✓ | <p>HMAC-SHA256 hashed signature of the concatenated method name with all argument values using the terminal password as private key</p> |

<h1><a id="3DSecure"></a>Administrative Message – 3D Secure OTP</h1>
<p>Sends message with 3D Secure OTP</p>
<p> </p>
<p>KLV data – ‘3D Secure OTP’ = 900.</p>
<p><em data-renderer-mark="true">Only if the 3DS validation option is ‘SMS OTP’:</em></p>
<p>‘Original transaction amount ’ = 004, ‘merchant description’ = 043, original currency code ’ = 049.</p>
<p>KLV data – ‘3D Secure OTP RefCode’ = 934.</p>
<p><strong>For more information on KLV data, click <a href="https://developer.sprint.paymentology.com/companion-api/klv-lookup/">here</a></strong></p>

#### Path parameters

| Parameter | type | Limits | required | Description |
|---|---|---|:--:|---|
| terminalID | String | 10 characters | ✓ | <p>The Paymentology issued terminal id of the terminal requesting the transaction</p> |
| reference | String |  1-255 characters | ✓ | <p>The reference of the wallet the 3DS authentication is being actioned on</p> |
| messageName | String |  0-2048 characters | ✓ | <p>The name of the administrative message being sent</p> |
| messageData | String |  0-2048 characters | ✓ | <p>The administrative message data sent over in a <a href="https://developer.sprint.paymentology.com/companion-api/klv-lookup/">KLV format</a></p> |
| transactionID | String |  1-255 characters | ✓ | <p>Transaction id number generated by the calling client.</p> <p>Note that the Transaction id is not a unique value and may be duplicated over time</p> |
| transactionDate | Date |  | ✓ | <p>Transaction date generated by the calling client</p> |
| checksum | String |  | ✓ | <p>HMAC-SHA256 hashed signature of the concatenated method name with all argument values using the terminal password as private key</p> |

<h2><a id="3DSAppFinal"></a>Administrative Message – <strong data-renderer-mark="true">3DSecure.AppFinalisation</strong></h2>
<p>This message is used to inform the client of the final status of the 3DSecure OOB authentication.<br  />
Messages include the following:</p>

#### Path parameters

| Parameter | type | Limits | required | Description |
|---|---|---|:--:|---|
| terminalID | String | 10 characters | ✓ | <p>The Paymentology issued terminal id of the terminal requesting the transaction</p> |
| reference | String | 1-255 characters | ✓ | <p>The reference of the wallet the 3DS authentication is being actioned on</p> |
| messageName | String | 0-2048 characters | ✓ | <p>The name of the administrative message being sent: 3DSecureAppFinalisation</p> |
| messageData | String | 0-2048 characters | ✓ | <p>The adminisrative message data sent over in a <a href="https://developer.sprint.paymentology.com/companion-api/klv-lookup/">KLV format</a> will contain the following KLV fields: 274 – status.<br  /> Values indicating the status:<br  /> 0 – Successfully received final status<br  /> 1 – Timer on browser expired before response was received<br  /> 2 – General error<br  /> 3 – Transaction cancelled before response was received</p> |
| transactionID | String |  1-255 characters | ✓ | <p>Will be the unique transaction id provided by the ACS.</p> |
| transactionDate | Date |  | ✓ | <p>Transaction date generated by the calling client</p> |
| checksum | String |  | ✓ | <p>HMAC-SHA256 hashed signature of the concatenated method name with all argument values using the terminal password as private key</p> |
